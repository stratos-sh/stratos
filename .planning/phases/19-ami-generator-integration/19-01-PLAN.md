Integrate the Phase 18 warmup script generator into AL2 and AL2023 user data generators, adding image pull scripts as MIME parts when images are configured. Extract shared MIME utilities. Add user data size warning.

Output: Updated AL2/AL2023 generators that conditionally inject image pull scripts, shared MIME utilities, size warning, and comprehensive tests.
</objective>

  <action>
    **1. Create `mime.go`** -- Extract MIME utility functions from `al2023.go` into a new shared file:
    - Move `mimePartShellScript()` from al2023.go to mime.go (it's currently defined there, used by al2.go via same package)
    - Move `buildMIMEMultipart()` from al2023.go to mime.go
    - Add NEW `mimePartNodeConfig()` function that creates a MIME part with `Content-Type: application/node.eks.aws; charset="us-ascii"` and `filename="nodeadm-config.yaml"`
    - Add size check function: `checkUserDataSize(userData string) (string, error)` that returns error if >16384 bytes (hard limit), returns the userData unchanged otherwise. Use `log` package from controller-runtime (`sigs.k8s.io/controller-runtime/pkg/log`) to log warning if >14336 bytes (14 KiB, 85% threshold). Since generators don't have context, instead return the userData and a separate size warning string. The caller (or a wrapper) can log it. Actually, simpler: just return the userData string and error. For the warning case, use `fmt` to print to stderr as a fallback, OR better yet: return a UserDataResult struct with `Data string`, `SizeWarning string`, and `Error error`. But that changes the generator interface. Simplest approach: keep the generator interface returning `(string, error)`. Add a package-level function `WarnIfLargeUserData(userData, poolName string)` that logs using `fmt.Fprintf(os.Stderr, ...)` for now. The controller (Phase 20) will integrate proper structured logging. For the hard limit, return an error from the generator if size > 16384 bytes.
    - Keep `sortStrings()` in al2023.go (it's used there and in al2.go, but it's not MIME-related). Actually check where it's defined -- it's in al2023.go. Leave it there for now.

    **2. Update `userdata.go`** -- Add `PreWarmConfig` field to `BootstrapConfig`:
    ```go
    // PreWarmConfig is the optional pre-warm configuration from NodePool.Spec.PreWarm
    PreWarmConfig *stratosv1alpha1.PreWarmConfig
    ```
    This is the only change to userdata.go. The field is a pointer (nil when no PreWarm configured).

    **3. Update `al2.go`** -- Inject image pull MIME part between bootstrap and warmup:
    - Import `"github.com/stratos-sh/stratos/internal/warmup"`
    - In `Generate()`, after Part 1 (bootstrap script) and before the warmup script part:
      - Check `config.PreWarmConfig != nil && len(config.PreWarmConfig.Images) > 0`
      - If true, call `warmup.GenerateScript(config.PreWarmConfig.GetImages(), config.PreWarmConfig.GetImagePullPolicy())`
      - Add as MIME part: `mimePartShellScript(imagePullScript, "image-pull.sh")`
    - After building the full MIME multipart, check size: if `len(userData) > 16*1024`, return error with descriptive message including size, limit, and suggestion to reduce images.
    - If `len(userData) > 14*1024`, call `WarnIfLargeUserData(userData, config.PoolName)`.
    - The MIME part order MUST be: (1) bootstrap.sh, (2) image-pull.sh [conditional], (3) stratos-warmup.sh, (4) custom-userdata.sh [optional]. This ensures bootstrap runs first, then images are pulled (containerd must be ready), then warmup completion.
    - Remove the MIME functions from al2023.go since they're now in mime.go. Actually, check: `mimePartShellScript` and `buildMIMEMultipart` are currently defined in al2023.go. After moving to mime.go, remove them from al2023.go.

    **4. Update `al2023.go`** -- Add conditional MIME multipart:
    - Import `"github.com/stratos-sh/stratos/internal/warmup"`
    - In `Generate()`, after generating `nodeConfig`:
      - Check `hasImages := config.PreWarmConfig != nil && len(config.PreWarmConfig.Images) > 0`
      - If `!hasImages`: return `nodeConfig, nil` (existing behavior, plain YAML)
      - If `hasImages`: build MIME multipart with 3 parts:
        - Part 1: `mimePartNodeConfig(nodeConfig)` -- NodeConfig as `application/node.eks.aws`
        - Part 2: `mimePartShellScript(warmup.GenerateScript(...), "image-pull.sh")`
        - Part 3: `mimePartShellScript(getWarmupScript(), "stratos-warmup.sh")`
      - Call `buildMIMEMultipart(parts)` and check size same as AL2
    - Remove `mimePartShellScript()` and `buildMIMEMultipart()` definitions from this file (moved to mime.go)

    **Important constraints:**
    - Use `config.PreWarmConfig.GetImages()` and `config.PreWarmConfig.GetImagePullPolicy()` (nil-safe getters from Phase 17) -- NOT direct field access
    - The nil check on `config.PreWarmConfig` is still needed before calling getters, because we need to know whether to include the MIME part at all (empty images = no MIME part)
    - Fixed MIME boundary `==STRATOS_MIME_BOUNDARY==` (already used, deterministic)
    - Do NOT modify `bottlerocket.go` -- it uses TOML, not MIME
  </action>

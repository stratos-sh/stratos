<objective>
Add Bottlerocket image pre-pull validation that surfaces a status condition warning when images are configured on a NodePool using a Bottlerocket AMI. The warning is non-blocking -- instances still launch without cached images.

Purpose: Bottlerocket uses TOML config without shell script support, so image pre-pull cannot work. Users need a clear signal that their image configuration is being ignored for Bottlerocket pools.
Output: New condition type, validation function, and unit tests.
</objective>

    **2. Add validation function to `nodepool_validation.go`:**
    Add a new function `checkImagePrePullSupport` on the Reconciler:

    ```go
    // checkImagePrePullSupport checks if the AMI family supports image pre-pull
    // and sets/removes the ImagePrePullSupported condition accordingly.
    // This is non-blocking -- Bottlerocket instances still launch without cached images.
    func (r *Reconciler) checkImagePrePullSupport(
        nodePool *stratosv1alpha1.NodePool,
        nodeClass stratosv1alpha1.NodeClass,
    ) {
    ```

    Logic:
    - Check if images are configured: `nodePool.Spec.PreWarm != nil && len(nodePool.Spec.PreWarm.Images) > 0`
    - If no images configured: remove the condition entirely with `meta.RemoveStatusCondition(&nodePool.Status.Conditions, stratosv1alpha1.ConditionTypeImagePrePullSupported)` and return
    - If images configured, type-assert NodeClass to `*stratosv1alpha1.AWSNodeClass`:
      - If assertion fails (non-AWS), skip (no condition set)
      - If `awsNodeClass.Spec.BootstrapTemplate == stratosv1alpha1.BootstrapTemplateBottlerocket`:
        - Set condition: Type=ImagePrePullSupported, Status=ConditionFalse, Reason=BottlerocketNotSupported, Message="Image pre-pull is not supported on Bottlerocket AMIs. Instances will launch without cached images."
      - Else (AL2 or AL2023):
        - Remove the condition if it was previously set (e.g., user changed AMI family): `meta.RemoveStatusCondition(&nodePool.Status.Conditions, stratosv1alpha1.ConditionTypeImagePrePullSupported)`

    **Important:** This function does NOT call `r.Status().Update()`. It only mutates the in-memory conditions. The caller (reconciler) is responsible for persisting status. This matches the pattern of `setReadyCondition` which also just mutates in-memory.

    **Important:** Do NOT block instance launch. This is purely informational. The function returns nothing (void).

    **Import note:** The function needs `"k8s.io/apimachinery/pkg/api/meta"` and `metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"` -- both are already imported in nodepool_validation.go.

  <name>Task 2: Add tests for Bottlerocket image pre-pull validation</name>
  <files>

  <action>
    Create a NEW test file `nodepool_validation_test.go` in the `nodepool` package. Since `checkImagePrePullSupport` is a method on `*Reconciler`, and the function only reads from the NodePool/NodeClass structs (no API calls), we can test it by constructing a minimal Reconciler and calling the method directly.

    However, `Reconciler` likely embeds `client.Client` and other fields. Since `checkImagePrePullSupport` does NOT use `r.Get`, `r.Client`, etc. (it only mutates in-memory), we can create a Reconciler with zero-value/nil fields for testing. BUT -- this is fragile. Better approach: make the core logic a standalone function that takes `(nodePool, nodeClass)` and the Reconciler method delegates to it. Actually, simplest approach: test as a package-level test using the Reconciler type. The function only accesses `nodePool.Status.Conditions` and `nodeClass` (type assertion), so a nil-client Reconciler works fine since no API calls are made.

    Test cases:

    1. `TestCheckImagePrePullSupport_BottlerocketWithImages` -- NodePool with images + AWSNodeClass with BootstrapTemplateBottlerocket. Assert:
       - Condition ImagePrePullSupported is set
       - Status is ConditionFalse
       - Reason is BottlerocketNotSupported
       - Message contains "not supported" and "Bottlerocket"

    2. `TestCheckImagePrePullSupport_AL2023WithImages` -- NodePool with images + AWSNodeClass with BootstrapTemplateAL2023. Assert:
       - Condition ImagePrePullSupported is NOT set (removed)

    3. `TestCheckImagePrePullSupport_AL2WithImages` -- NodePool with images + AWSNodeClass with BootstrapTemplateAL2. Assert:
       - Condition ImagePrePullSupported is NOT set

    4. `TestCheckImagePrePullSupport_BottlerocketNoImages` -- NodePool without images + AWSNodeClass with BootstrapTemplateBottlerocket. Assert:
       - Condition is NOT set (no images = no warning needed)

    5. `TestCheckImagePrePullSupport_NilPreWarm` -- NodePool with nil PreWarm + any NodeClass. Assert:
       - Condition is NOT set

    6. `TestCheckImagePrePullSupport_RemovesPreviousCondition` -- NodePool that already has ImagePrePullSupported=False condition, then called with AL2023 NodeClass. Assert:
       - Condition is removed (user switched from Bottlerocket to AL2023)

    **Test helper construction:**
    - NodePool: `&stratosv1alpha1.NodePool{Spec: stratosv1alpha1.NodePoolSpec{PreWarm: &stratosv1alpha1.PreWarmConfig{Images: []string{"nginx:latest"}}}}`
    - AWSNodeClass: `&stratosv1alpha1.AWSNodeClass{Spec: stratosv1alpha1.AWSNodeClassSpec{BootstrapTemplate: stratosv1alpha1.BootstrapTemplateBottlerocket}}`
    - Reconciler: `&Reconciler{}` (zero-value, no API calls needed)

    **Assertion helper:** Use `meta.FindStatusCondition(nodePool.Status.Conditions, stratosv1alpha1.ConditionTypeImagePrePullSupported)` to check presence and values.

    Import `"k8s.io/apimachinery/pkg/api/meta"` for `FindStatusCondition`.

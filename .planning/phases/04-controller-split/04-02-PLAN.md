  <action>
    Create `internal/controller/nodeclass/` directory.

    **reconciler.go** -- Convert nodeclass_lifecycle.go into a proper reconciler:
    1. Change `package controller` to `package nodeclass`
    2. Create a new `Reconciler` struct with only the fields needed:
       ```go
       type Reconciler struct {
           client.Client
           Scheme *runtime.Scheme
       }
       ```
    3. Add a `Reconcile(ctx, req)` method that:
       - Fetches the AWSNodeClass by name from the request
       - If not found, return (no requeue) -- the object was deleted
       - If being deleted (DeletionTimestamp set): run cleanup logic (remove in-use finalizer if no NodePools reference it), then return
       - Otherwise: count referencing NodePools, manage finalizer (add if referenced), update status (nodePoolCount, conditions: InUse, Valid)
       - This is a new reconciler watching NodeClass objects AND NodePool events (via watcher in setup.go)
    4. Convert all existing `(r *NodePoolReconciler)` methods to `(r *Reconciler)`:
       - `getAWSNodeClass` -> same, receiver changes
       - `getNodeClass` -> same
       - `updateNodeClassLifecycle` -> becomes the core of the Reconcile() method (inline the logic, not a separate method call)
       - `cleanupNodeClassReference` -> becomes the deletion handler within Reconcile() (called when DeletionTimestamp is set)
       - `countNodePoolsReferencingNodeClass` -> same
       - `countNodePoolsReferencingNodeClassExcluding` -> same (used during deletion to count remaining pools)
       - `getInUseCondition` -> same
       - `getValidCondition` -> same
       - `conditionMatches` -> stays as package-level function
    5. The Reconcile() method handles ALL NodeClass lifecycle events, including those triggered by NodePool changes. When a NodePool is created/updated/deleted, the NodePool watcher (in setup.go) enqueues the referenced NodeClass for reconciliation. The reconciler then recounts NodePools and updates accordingly. This means:
       - NodePool creation/update: NodeClass gets reconciled, pool count increases, finalizer added if needed
       - NodePool deletion: NodeClass gets reconciled, pool count decreases, finalizer removed if count reaches zero
       - No cross-package calls from nodepool -> nodeclass are needed

    **setup.go** -- Register the NodeClass controller:
    1. Create `Setup(mgr ctrl.Manager) error` function (no options struct needed -- NodeClass reconciler only needs Client and Scheme from mgr)
    2. Define `nodePoolToNodeClassHandler` as a package-level function in this file. It returns a `handler.EnqueueRequestsFromMapFunc` that:
       - Takes the NodePool object from the event
       - Extracts `nodePool.Spec.Template.NodeClassRef.Name`
       - Returns a `[]reconcile.Request` with a single request for the referenced NodeClass name
       - Handles nil/empty NodeClassRef gracefully (return empty slice)
    3. Register the controller:
       ```go
       ctrl.NewControllerManagedBy(mgr).
           For(&stratosv1alpha1.AWSNodeClass{}).
           Watches(&stratosv1alpha1.NodePool{}, handler.EnqueueRequestsFromMapFunc(nodePoolToNodeClassMapper)).
           Named("nodeclass").
           Complete(r)
       ```
       This watches both AWSNodeClass (primary) and NodePool (secondary) events. When ANY NodePool event fires (create, update, delete), the referenced NodeClass is enqueued for reconciliation.

    **reconciler_test.go** -- Convert nodeclass_lifecycle_test.go:
    1. Change `package controller` to `package nodeclass`
    2. Replace all `NodePoolReconciler{Client: ...}` with `Reconciler{Client: ...}`
    3. Import paths stay the same (tests reference api/v1alpha1 types, not controller types)
    4. The test helper functions and test structure remain the same -- only the reconciler type changes

    Delete originals from controller/ root:
    - `internal/controller/nodeclass_lifecycle.go`
    - `internal/controller/nodeclass_lifecycle_test.go`
  </action>

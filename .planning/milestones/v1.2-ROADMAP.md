# Milestone v1.2: Warmup Image Pre-Pull

**Status:** SHIPPED 2026-02-05
**Phases:** 17-20
**Total Plans:** 5

## Overview

Standby nodes have expected container images cached, eliminating image pull latency when pods are scheduled. Users can configure `spec.preWarm.images` on NodePool to specify which images to pre-pull during the warmup phase, with either Required (default) or BestEffort pull policy.

## Phases

### Phase 17: CRD Types and Code Generation

**Goal**: NodePool CRD accepts warmup image configuration with validated fields and generated deepcopy methods
**Depends on**: Nothing (first phase of v1.2; builds on existing PreWarmConfig struct)
**Plans**: 1 plan

Plans:
- [x] 17-01: Add ImagePullPolicy type, PreWarmConfig fields, getters, tests, and code generation

**Details:**
- ImagePullPolicy string type with Required and BestEffort constants (PascalCase)
- PreWarmConfig has Images []string with per-item minLength:1 validation
- PreWarmConfig has ImagePullPolicy pointer field with enum + default
- Nil-safe GetImages() and GetImagePullPolicy() getters
- Deepcopy correctly handles Images slice and ImagePullPolicy pointer
- CRD YAML contains images array and imagePullPolicy enum

### Phase 18: Warmup Script Generator

**Goal**: A warmup script generator produces correct bash that pulls configured images using ctr, with ECR auth, retry logic, pinning, and policy-aware failure handling
**Depends on**: Phase 17 (uses ImagePullPolicy type for policy-aware generation)
**Plans**: 1 plan

Plans:
- [x] 18-01: Warmup script generator package with template, ECR auth, retry, pinning, and tests

**Details:**
- Created `internal/warmup/` package with GenerateScript function
- Containerd readiness detection with 60s timeout
- ECR authentication via pattern matching and `aws ecr get-login-password`
- Retry with exponential backoff (3 attempts, 2s/4s/8s delays)
- Image pinning with `io.cri-containerd.pinned=pinned` label
- Policy-aware error handling (Required exits 1, BestEffort always exits 0)
- No-op script for empty image lists

### Phase 19: AMI Generator Integration

**Goal**: Image pull script is correctly injected into user data for AL2 and AL2023 instances, with a validation warning for Bottlerocket
**Depends on**: Phase 18 (uses warmup script generator output)
**Plans**: 2 plans

## Milestone Summary

**Key Decisions:**
- Image pre-pull config lives on NodePool spec (not AWSNodeClass) -- images are a workload concern
- Required is the default imagePullPolicy -- stricter ensures standby nodes have expected images
- Use ctr exclusively (not crictl) -- crictl missing on AL2023, ctr universal on all EKS AMIs
- Image pinning with io.cri-containerd.pinned=pinned is mandatory -- prevents kubelet GC eviction
- Flat sequential bash script for warmup (not functions) -- simpler to generate and debug
- AL2023 conditionally switches from plain YAML to MIME multipart -- backward compatible
- PreWarmConfig as pointer field on BootstrapConfig -- nil means no pre-warm configured
- checkImagePrePullSupport is non-blocking -- sets condition but doesn't prevent launch

**Issues Resolved:**
- None (clean implementation)

**Issues Deferred:**
- Bottlerocket image pre-pull -- requires bootstrap-containers approach; immutable OS
- Dynamic pending-pod image pull -- no clean mechanism without API server access
- Per-image pull policy -- CRD complexity not justified
- Configurable retry count -- hardcoded sensible defaults

**Technical Debt Incurred:**
- ReasonImagePrePullSupported constant defined but unused -- defined for symmetry; harmless
